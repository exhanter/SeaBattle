# Sea Battle · пакет для реализации в Xcode

Редизайн приложения «Морской бой» (iOS, SwiftUI, EN / RU / NL). Направление дизайна —
**«Стекло и латунь»**: море как фон, интерфейс как стекло над ним, тёплый латунный
акцент за игрока и холодный лазурный за противника.

## Что в пакете

| Файл | Что это | Как читать |
| --- | --- | --- |
| `README.md` | этот файл | первым |
| `CHANGES.md` | ответы на все вопросы агента (R1.1 – R2.3, раунды 4–7) и что сделать у себя | вторым, если сборка уже начата |
| `SPEC.md` | **главный документ**: компоненты, экраны, поведение, движение, порядок сборки из 18 шагов | целиком |

## Важно про макеты

`mockups.html` — это **дизайн-референс, а не код к переносу**. Макеты собраны в HTML,
чтобы показать вид и поведение; в приложении всё это пишется на SwiftUI с нуля.
Из HTML не нужно брать ни разметку, ни CSS — только смотреть на результат и сверяться.

Макеты **высокой точности**: цвета, размеры, отступы и радиусы в них финальные, их
можно замерять. Все значения уже выписаны в `DesignTokens.swift`, `Colors.xcassets` и
`TOKENS.md`. Если они расходятся с макетами, правы `DesignTokens.swift` и каталог.

## Порядок работы

1. Прочитать `SPEC.md` от начала до конца. Раздел 1 (семь правил) — ограничения, а не
   пожелания: из них следует бо́льшая часть решений по раскладке.
2. Перетащить в проект `Colors.xcassets` и `DesignTokens.swift`. Каталог собран
   автоматически из того же списка, что файл токенов, и проверен на совпадение имён —
   **вручную ничего не заводить.** Альфа входит в цвет ассета. В коде не должно быть
   ни одной проверки `colorScheme`: тема переключается сама, раскладка не меняется.
3. Идти по разделу 6 спеки, «Порядок сборки». 18 шагов расположены так, что каждый
   заканчивается тем, что можно запустить и посмотреть; начинается всё с токенов и
   `CellView`, потому что клетка — самый переиспользуемый элемент в игре.
4. Сверять результат каждого шага с соответствующим блоком в `mockups.html`. Блоки
   подписаны номерами (3a — состояния клетки, 15b — таблица токенов, 14c — длительности
   анимаций); в спеке эти номера указаны.

## Ориентиры в макетах

Страница длинная и грузится по мере прокрутки. Блоки, которые нужны чаще всего:

- **15a–15c** — палитра, таблица цветовых токенов, геометрия и шрифт.
- **3a** — шесть состояний клетки в обеих темах, эталон для `CellView`.
- **3b** — обвязка поля B1 и B2.
- **14a–14d** — анимации: раскадровки, переходы, таблица длительностей и живое демо
  (в **14d** анимации реально играют, есть замедление ×3,2 и повтор).
- **4a–4g** — игра на бумаге, меню, бой, малые экраны, компоновка iPad.
- **5a–5d** — расстановка, настройки, уровни одиночной игры, сетевые режимы.
- **7a–8b** — расстановка подробно: дрожание, перемещение, запрещённая позиция.
- **10a–13a** — итоги, статистика, достижения, Pro, кошелёк, первый запуск, пустые
  состояния.

## Технический таргет

- iOS 18 минимум. Дизайн-база — нормы iOS 26 Liquid Glass; на iOS 18 стекло подменяется
  системными материалами, **раскладка и размеры не меняются**.
- iPhone: 393 pt основной, 375 pt (SE, mini) проверен отдельно. iPad: обе ориентации.
- Языки EN / RU / NL. Ширина текста нигде не фиксируется: подписи разной длины.
- Доступность: Reduce Motion (правила в разделе 5 спеки), Dynamic Type, VoiceOver для
  клеток поля — координата и состояние.

## Что ещё не решено

- Итоговые цены Pro: 1 490 / 790 / 149 ₽ — заглушки, вёрстка выдержит и один вариант.
- Витрина за баллы: экран готов, состава товаров нет.
- Звуковые файлы предоставляет заказчик. В спеке только привязка звука к событиям.

Ничто из этого не блокирует сборку.
