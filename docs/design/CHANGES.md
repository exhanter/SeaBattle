# Изменения пакета · сверка после R1.1

Документ закрывает все вопросы по токенам, заданные в R1.1 (два раунда). Все ответы
ниже уже внесены в файлы пакета. Сверять ничего не нужно, кроме того, что перечислено
в разделе «Что сделать у себя».

## Главное изменение: каталог цветов теперь в пакете

`Colors.xcassets` собран заранее и лежит в пакете: 73 цвета, семь папок с включённым
**Provides Namespace**, поэтому имена вида `Color("Sea/Top")` работают как есть.
Каталог, `TOKENS.md`, таблица 15b в `mockups.html` и `DesignTokens.swift` сгенерированы
из **одного списка** и перед сборкой автоматически проверены: множество имён
`Color("…")` в Swift совпадает с множеством ассетов один в один. Сверять вручную
больше не нужно.

**Замените свой каталог на каталог из пакета целиком.** Значения, которые вы заводили
сами по коду макетов, теперь есть в каталоге. Пометки об источнике значений можно
убрать.

## Ответы на вопросы

### Раунд 1

1. **Sea/Mid — 46 % в обеих темах.** 48 % в светлой теме появилось случайно.
   Правило: геометрия задаётся в коде и одна на обе темы, в ассеты уходят только цвета.
2. **Дышит только слой свечения**, градиент моря неподвижен. Токен `Sea/Glow`:
   тёмная `rgba(120,220,220,.30)`, светлая `rgba(210,255,250,.34)`. Разные значения
   0.30 / 0.32 / 0.35 в макетах — случайность. Вылет −40 pt — артефакт HTML, в SwiftUI
   его заменяет `scaleEffect` внутри обрезающего контейнера. При Reduce Motion
   свечение застывает на средних значениях (`scale 1.07`, `offset 0`, `opacity 1`)
   и не исчезает.
3. **Таблица 15b — единственный источник**, теперь полная.
   `Cell/HullFoe*` удалены: они нужны только для разбора партии, который отложен.
   У пробоины F4 четыре кромки. Кресты F4 и S4 — разные токены: крест F4 лежит на воде
   и в светлой теме меняется ролями с обводкой, крест S4 лежит на стали и оранжевый
   в обеих темах.

### Раунд 2

1. **Компиляция.** Лишняя скобка убрана. Ваш вариант
   `extension RadialGradient { static func seaGlow(in size: CGSize) }` взят в файл без
   изменений, кроме одного: прозрачная точка стоит на `location: 0.70`, а не `1`.
   В макете свечение гаснет на 70 % радиуса, без этой точки пятно получается шире.
   Радиус — 60 % ширины области. Эллипс 60 × 40 из CSS в SwiftUI заменён кругом,
   разница на глаз не видна.
2. **Токены стекла возвращены**: `Glass/Shadow`, `Glass/Raised*` (пять токенов),
   `Glass/SolidStroke`, бевели корпуса (`Cell/HullSheen`, `Cell/HullShade`) и стали
   (`Cell/SteelSheen`, `Cell/SteelShade`). Вы правильно сделали, что оставили их у себя.
3. **G2 — градиент в обеих темах.** В тёмной теме `Glass/Fill2` = `Glass/Fill` =
   `rgba(255,255,255,.14)`, поэтому заливка выглядит ровной. Спад `.14 → .05` отклонён:
   на панелях разной высоты нижние края светлели бы по-разному. Значение `.05` осталось
   только у `Glass/RaisedFill2` в G3.

  **`Ink/Primary` (белая)**, не `Ink/OnBrass`, как ошибочно было в спеке 2.6. Неактивная

## Что сделать у себя

1. Заменить `Colors.xcassets` и `DesignTokens.swift` файлами из пакета.
2. G2 собирать градиентом `Fill → Fill2` под 135° в обеих темах. Веток по теме нет.
3. `PrimaryButton`: надпись `Ink/Primary`, остальное — по `Button/*` (спека 2.6).
4. Собрать, проверить экраном-полоской всех 73 токенов в двух темах (шаг 1 порядка
   сборки) и переходить к R1.2.

Если найдётся новое расхождение, источник истины — `DesignTokens.swift` вместе
с `Colors.xcassets`.
